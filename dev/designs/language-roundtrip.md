# Round-Trip, Identity, and Diagnostics

Coral text and GraphIR are converted in both directions constantly — the editor prints on every visual edit and parses on every keystroke — so `print` and `parse` are treated as a loop rather than two independent functions. The loop is not required to reproduce source text: comments and blank lines are dropped, edges are re-emitted after all nodes, indentation is normalised, and every edge attribute is emitted as `key: value` to match the node-property spelling. What is required is that the loop reach a fixpoint on its second application, that identity survive it, and that anything the surface cannot carry be reported rather than lost. A parse also survives its own failures: `parse` reports the offending line and continues to the next, `parseDot` catches at the statement boundary and returns the statements completed before the failure, both return the graph they built alongside `success: false`, and `useBidirectionalSync` adopts that partial graph rather than discarding it.

Quoting is one pair of functions used by both sides. One escaper and one unescaper are inverse over `\`, `"`, newline, carriage return and tab, and every quoted position — node label, property value, edge attribute, and the id spellings below — is written by the first and read by the second, so a label survives any number of passes rather than growing a backslash on each. Attribute lists are scanned rather than split, so a `,` or a `]` inside a quoted value is not a delimiter, and a property key outside the bare identifier charset is emitted quoted and accepted quoted.

Identity is the hard part, because Coral text names nodes by label and GraphIR names them by id. The parser derives an id from each label; a graph whose ids were assigned elsewhere — by the DOT importer, by the visual editor after a rename — therefore loses every edge when printed, silently. The language gains `<type> "<label>" as <id>` to close that gap, and both the id clause and edge endpoints accept either a bare identifier or a quoted string, so ids containing whitespace or punctuation round-trip instead of producing text that cannot be parsed at all. Edge ids are not preserved: they are re-derived from endpoints and reported as `coral.edge.id.dropped`.

Id allocation is one function used by both sides. `generateNodeId` keeps a document-wide set of taken ids, derives a base from the label, substitutes a deterministic fallback when that base is empty, and returns the first of `base`, `base_2`, `base_3` … not already taken; `reserveNodeId` adds an id without allocating, and `releaseNodeId` returns one to the set. `generateEdgeId` works the same way over its own set. The parser reserves on an `as` clause and allocates otherwise; a reservation whose id is already taken cannot be honoured, so the parser allocates a fresh id for that declaration, rewrites edges referencing it, and reports `coral.node.id.degraded`.

A pre-pass makes the input safe before the printer replays any of that. Two nodes handed to `print` sharing an id — neither `setFromVisual` nor `convertToCoralDsl` checks — leave the first with its id and allocate a fresh one for each other; an empty id, which neither spelling expresses, is replaced by a derived one. Both cases build one substitution map, applied to `edge.source` and `edge.target` as well as to the node so no edge is left pointing at a name with no spelling, and each substitution is reported as `coral.node.id.degraded`. The forward pass therefore always sees unique, non-empty ids.

The printer then replays the same allocator over the same declaration order in a single forward pass, deciding each node before moving to the next. It allocates from the label it will actually emit — `node.label` when the field is present, including the empty string, and `node.id` when it is absent — and keeps the allocation when it equals `node.id`. Otherwise it releases the speculative id back to the taken set, so a later node may still receive it, marks the node explicit, and reserves `node.id` instead. The pass decides each node in turn rather than deciding all of them before applying any, which would over-annotate.

Diagnostics are a single channel with three severities behind a dotted `<producer>.<construct>.<disposition>` code. `Diagnostic` carries an optional `SourcePosition` — named so because `Position` is already GraphIR's `{ x, y }` — and `ParseDiagnostic` extends both `Diagnostic` and the unchanged `ParseError`, requiring the position and mirroring it into the flat `line`, `column` and `offset` fields that the MCP tools and the editor gutter read. One builder constructs every parse result: it orders the diagnostics by source position, derives `errors` as the error-severity view of that ordered array so the two are element-identical and in the same order, derives `success` from the absence of errors so a warning never fails a parse, and freezes both. `dot.ts`'s tokenizer emits positioned tokens rather than bare strings, and `stripComments` replaces comment text with equivalent whitespace so token offsets remain offsets into the original source.

Print diagnostics do not pass through that builder — they carry no position to order by and no result to succeed or fail — so `printWithDiagnostics` returns bare `Diagnostic`s in emission order. It owns the single traversal that both emits text and records what it declined to emit, so the two cannot disagree; `print` and `prettyPrint` are that function with the diagnostics dropped into a null sink, keeping their string signatures for external consumers and allocating nothing per node or edge.

Two in-repo adoptions remain for 0.2.4. `@coral-viz/diagram-editor` exposes `printCoralDSLWithDiagnostics` and uses it while switching formats, but ordinary diagram-to-text synchronization still calls the silent wrapper; the state extraction must route every print diagnostic to the shell's diagnostics surface. MCP `coral_convert` now uses `printWithDiagnostics`, while MCP `coral_generate` still hand-writes unescaped Coral text; generation must build GraphIR and delegate to the shared printer, and the obsolete emitter is then removed. `@coral-viz/viz`'s separately declared `ParseResult` and `ParseError` have become `SyncParseResult` and `SyncParseError`, with the old names kept as deprecated aliases so the published surface stays additive.

This design does not give the Tree-sitter grammar parity with the runtime parser — the grammar gains the `as` clause and nothing else, and the portable TypeScript parser remains the supported surface. It does not preserve edge ids. And it does not carry geometry: node `position`, `pinned` and edge `routingPoints` stay out of the text surface until the geometry-authority design puts them there.
