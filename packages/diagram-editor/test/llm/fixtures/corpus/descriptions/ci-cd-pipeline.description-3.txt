By the end of this pipeline, code has been deployed to the Production Environment and is being watched by a Monitoring Service, but a long chain of steps gets it there. A Developer starts things off by pushing a commit into the Source Repository, which fires a webhook at the CI Server. The CI Server kicks off the Lint Stage, and a pass there moves things to the Unit Test Stage, and a pass there moves things to the Build Stage. The Build Stage does two things: it pushes a built image to the Container Registry, and it triggers the Security Scan Stage. A pass at the Security Scan Stage advances to the Integration Test Stage, which also separately pulls the image it needs from the Container Registry. Passing integration tests advances the pipeline to the Artifact Store, which triggers a deploy on the CD Server. The CD Server's first deploy target is the Staging Environment, which requests promotion through Manual Approval; once approved, that approval signals back to the CD Server, which then deploys to the Production Environment. The Production Environment reports its health back to the Monitoring Service, which alerts the Notification Service if anything fails, and independently of all that, the CI Server also reports its own status straight to the Notification Service.
