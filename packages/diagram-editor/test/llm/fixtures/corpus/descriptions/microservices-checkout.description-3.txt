Picture a customer checking out: the request eventually results in a card being charged through Stripe, but it passes through a lot of internal services first. Everything begins when the Client App issues an HTTPS request into the API Gateway, the single front door for the architecture. From there the gateway fans out to three internal services — Auth Service (for authentication), User Service (for user-related routes), and Order Service (for order-related routes). The Auth Service checks the User Database to verify credentials; the User Service independently reads and writes user profile data in that same User Database. Once an order request reaches the Order Service, four things happen off of it: the order gets persisted into the Order Database, the Inventory Service is called to check stock, the Payment Service is called to charge the customer, and the Notification Service is called to send a confirmation. The Payment Service is the one that actually reaches outside the system, calling the external Stripe API to process the payment.
