This diagram shows an OAuth authorization code flow across seven participants: a User, a Client App, an Authorization Server, an Identity Provider, a Consent Service, a Token Store, and a Resource Server. The User clicks login in the Client App. The Client App sends an authorization request to the Authorization Server, which redirects to the Identity Provider for authentication. The User submits credentials directly to the Identity Provider, which confirms the identity back to the Authorization Server. The Authorization Server then requests user consent from the Consent Service; the User approves scopes directly with the Consent Service, which grants consent back to the Authorization Server. The Authorization Server stores an authorization code in the Token Store and returns that authorization code to the Client App. The Client App exchanges the code for a token by calling the Authorization Server, which validates the code with the Token Store (getting back "code valid") and returns an access token to the Client App. The Client App then requests a protected resource from the Resource Server using the token; the Resource Server validates the token with the Authorization Server (getting back "token valid") and finally returns the protected resource to the Client App.
