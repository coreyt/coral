The Sender ends up with a delivery receipt in hand, the last of ten messages exchanged. That receipt comes from the Chat Service, which only issues it after the Message Queue reports "message delivered". The Message Queue only reports that after the Recipient Device sends back a delivery ack, which itself only happens because the Message Queue delivered the message to the Recipient Device in the first place. Earlier in the flow, before any of that delivery activity, the Chat Service had queried the Presence Service and learned the recipient was offline, which prompted it to route through the Push Notification Service (getting back "notification queued"). All of this traces back to the very first step: the Sender handing the message to the Chat Service, which immediately enqueued it with the Message Queue.
