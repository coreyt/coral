This diagram shows a two-phase-commit-style distributed transaction with eight participants: a Client, a Transaction Coordinator, an Order Service, an Inventory Service, a Payment Service, an Order Database, an Inventory Database, and a Payment Database. The Client tells the Coordinator to begin a transaction. In the prepare phase, the Coordinator sends "prepare(order)" to the Order Service, which writes a pending order to the Order Database and gets back "write ok"; the Order Service then votes commit back to the Coordinator. The Coordinator sends "prepare(reserve stock)" to the Inventory Service, which writes a pending reservation to the Inventory Database and gets back "write ok"; the Inventory Service then votes commit back to the Coordinator. The Coordinator sends "prepare(charge)" to the Payment Service, which writes a pending charge to the Payment Database and gets back "write ok"; the Payment Service then votes commit back to the Coordinator. Once all three participants have voted commit, the Coordinator sends a "commit" message to the Order Service, a "commit" message to the Inventory Service, and a "commit" message to the Payment Service, and finally confirms to the Client that the transaction committed.
