This diagram models a CI/CD pipeline with sixteen components. It begins when the Developer pushes a commit to the Source Repository. The Source Repository triggers a webhook to the CI Server. The CI Server runs the Lint Stage, which upon passing hands off to the Unit Test Stage, which upon passing hands off to the Build Stage. The Build Stage pushes an image to the Container Registry and also triggers the Security Scan Stage. Once the Security Scan Stage passes, it hands off to the Integration Test Stage; separately, the Container Registry pulls the image into the Integration Test Stage as well. Once the Integration Test Stage passes, it hands off to the Artifact Store, which triggers a deploy on the CD Server. The CD Server deploys to the Staging Environment, which requests promotion from Manual Approval. Once Manual Approval approves, it signals back to the CD Server, which then deploys to the Production Environment. The Production Environment reports its health to the Monitoring Service, which alerts the Notification Service on failure. Separately, the CI Server also reports its status directly to the Notification Service.
