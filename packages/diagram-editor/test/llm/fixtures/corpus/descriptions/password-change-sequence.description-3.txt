By the end, the User sees a success message confirming their password was changed. That result comes from a chain starting when the User submits their current and new password to the WebApp, which requests a password change from the AuthService. The AuthService first verifies the current password hash with the UserDB, and once the UserDB confirms the hash is valid, the AuthService stores the new password hash back in the UserDB. The AuthService then confirms the change to the WebApp, which relays a success message back to the User.
