Seven components take part: User, Client App, Authorization Server, Identity Provider, Consent Service, Token Store, and Resource Server. The User connects to three others: clicking login in the Client App, submitting credentials directly to the Identity Provider, and approving scopes directly with the Consent Service. The Client App connects to the Authorization Server (sending the authorization request, later exchanging the code for a token and receiving the access token, having earlier received the authorization code) and to the Resource Server (requesting a resource with the token and receiving the protected resource back). The Authorization Server is the hub: besides its exchanges with the Client App, it redirects the Identity Provider for authentication and receives "identity confirmed" back, requests consent from the Consent Service and receives "consent granted" back, stores the authorization code in the Token Store, validates the code with the Token Store (receiving "code valid"), and later validates a token for the Resource Server (receiving the validation request and replying "token valid").
