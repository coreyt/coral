Four participants appear here: Client, Web Server, Auth Service, and Database, connected by nine total messages. The Client only ever talks to the Web Server, sending it a login request ("POST /login (username, password)") and later receiving one of two possible replies from it — either "200 OK + session token" or "401 Unauthorized". The Web Server, besides talking to the Client, forwards a "validateCredentials(username, password)" call to the Auth Service and gets back either "auth token" or "authentication failed" in response. The Auth Service does the most work: it queries the Database ("SELECT user WHERE username = ?") and gets a "user record" back, checks its own password hash internally ("verify password hash"), and then reports one of the two outcomes back to the Web Server.
